# MZ-2500 IOCS グラフィックメモ

SLANG から MZ-2500 IOCS のグラフィック系 SVC を呼び出すための調査メモです。

## 前提

- このメモは `lib/iocs/MZ25IOCS_SVC.LIB` の試作実装に対応します。
- BASIC システム上での動作確認を前提にしています。
- 640x400 では、一部の IOCS が通常の SLANG ワーク領域に置いたパラメータブロックや文字列を読めない場合があります。

## 200ライン用と400ライン用

`PSET` と `SVMBL` は、200ラインと400ラインで呼び出し方法を分けています。

- `IOCS_PSET_RAW`
  - 640x200向け。
  - 通常の SLANG ローカルバッファを `HL` に渡します。

- `IOCS_PSET_RAW400`
  - 640x400向け。
  - BASIC と同じ低位ワーク領域 `$0CC0` にパラメータを置いて呼び出します。

- `IOCS_SVMBL`
  - 640x200向け。
  - 通常の SLANG ローカルバッファと文字列ポインタを使います。

- `IOCS_SVMBL400`
  - 640x400向け。
  - `$0CC0` にパラメータ、`$0CD0` に文字列本体をコピーしてから呼び出します。

## 低位ワーク領域を使う理由

BASIC の `PSET` / `SYMBOL` 相当処理も、内部では `$0CC0` 付近にパラメータを作ってから IOCS を呼んでいることを確認しました。

SLANG から通常のローカル配列を `HL` に渡すだけだと、640x400 の `PSET` / `SVMBL` では描画されませんでした。一方、BASIC と同じように低位ワーク領域へパラメータを置くと描画できます。

このため、400ライン用関数では `$0CC0` / `$0CD0` を一時ワークとして使います。長い文字列や同時利用する処理では、この範囲の上書きに注意してください。

## 画面ページ切り替え

`SVC_SCREN` の `A=1` は、単純なページ番号ではなく表示フラグを `L` に渡す仕様として扱います。PDF資料では 320x200x16色の組み合わせが `0,2` / `1,3` のように読めますが、BASIC バイナリと実動確認では `0,1` / `2,3` の組み合わせでした。

BASIC バイナリ内の `SVC_SCREN` 呼び出しを追った結果、320x200x16色では次の値を使っています。

```text
単独ページ表示:
  page 0 -> L=$02
  page 1 -> L=$04
  page 2 -> L=$03
  page 3 -> L=$05

重ね合わせ表示:
  page 0/1 -> L=$06
  page 2/3 -> L=$07
```

ライブラリでは、640x200x16色の 0/1 画面切り替え用に `IOCS_SCREEN` を残し、320x200x16色向けに `IOCS_SCREEN320` と `IOCS_SCREEN320_GROUP` を追加しています。

```slang
IOCS_SCREEN(BYTE GI, BYTE GO)          // 640x200x16色 0/1画面
IOCS_SCREEN320(BYTE GI, BYTE GO)       // 320x200x16色 0..3画面
IOCS_SCREEN320_GROUP(BYTE GI, BYTE GROUP)
```

`IOCS_SCREEN320_GROUP` は `GROUP=0` で page 0/1、`GROUP!=0` で page 2/3 を表示します。描画先ページは `GI` で指定します。

## スクロール

`IOCS_HROLL(BYTE MODE, WORD Y)` を追加しています。

- `MODE = 0`
  - `Y` を指定してハードウェアスクロールします。

- `MODE != 0`
  - Cy=1 で `SVC_HROLL` を呼び、スクロール状態を初期化します。

`examples/iocs/GTEST.SL` では、パレット変更表示中に ESC を押したあと、`IOCS_HROLL` を使ったスクロールを確認できます。

320x200x16色の重ね合わせ表示で確認したところ、`IOCS_HROLL` はページ単位ではなく現在のグラフィック表示全体に効きます。たとえば page 0/1 を重ね合わせている場合、片方のページだけではなく両方のページが同時にスクロールします。

このため、背景ページだけをスクロールして前景ページを固定する用途には向きません。ページ別スクロールやスプライト風描画は、VRAM直接操作によるソフトウェア処理で実装する方針です。
